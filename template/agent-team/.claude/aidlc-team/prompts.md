# 操作提示詞速查表

啟動（在專案目錄）：Git Bash `CLAUDE_CODE_FORK_SUBAGENT=0 claude --agent pm`；PowerShell `$env:CLAUDE_CODE_FORK_SUBAGENT = "0"; claude --agent pm`。

以下都是**直接對 PM 說的話**，用自然語句即可，不必一字不差。對話中隨時問「有哪些指令」或「說明」，PM 會列出本表。

## 1. 開始與結束

| 想做的事 | 對 PM 說 | 說明 |
| --- | --- | --- |
| 開始一項工作 | 直接描述需求，例如「新增 GET /items/:id，id 不是正整數回 400，找不到回 404」 | 需求越具體，BA 的問題越少 |
| 中斷後繼續 | 重新啟動（同上方的啟動指令，要帶 `CLAUDE_CODE_FORK_SUBAGENT=0`）後說「從上次繼續」 | PM 讀 `aidlc-docs/aidlc-state.md` 接續 |
| 先停下來 | 「先停下」 | 任何模式都會在下一個點停住等你 |
| 放棄這項工作重來 | 結束 Claude Code，把 `aidlc-docs/` 改名備份後重新啟動 | 不改名的話 PM 會接續舊紀錄 |

## 2. 查看狀態

| 想做的事 | 對 PM 說 | PM 會回報 |
| --- | --- | --- |
| 看進度 | 「進度？」 | 目前階段與負責角色、已完成／待執行階段、進行中的回饋迴圈、未解問題、你下一步要做的事 |
| 看版本 | 「目前版本？」 | Personal-AI-DLC 版本與規則庫版本（也可看 `.claude/aidlc-team/VERSION`） |
| 看目前的設定 | 「目前的模式和設定？」 | 核准模式、風險等級、技術模組、擴充啟用狀態（記錄在 `aidlc-state.md`） |
| 看有哪些指令 | 「有哪些指令」或「說明」 | 本表 |

## 3. 核准模式（停下來等你的次數）

預設**依風險**：PM 在流程規劃時判定風險，低 → 自動、中 → 標準、高 → 強化。

| 對 PM 說 | 停點 | 適合 |
| --- | --- | --- |
| 「用自動模式」 | 只停 ⓒ 最終交付；問題自動採用建議答案，交付時列出這些假設 | 補測試、改訊息、小重構 |
| 「用標準模式」 | ⓐ 規格與介面、ⓒ 最終交付 | 一般功能、新增 endpoint |
| 「用強化模式」 | ⓐ、ⓑ 資料模型與基礎設施設計、ⓒ；高風險檔案逐行審查 | migration、IAM、有狀態資源 |
| 「用嚴格模式」 | 每個階段都停（含程式碼產生計畫） | 想逐步看過的重要變更 |
| 「依風險決定」 | 回到預設 | — |

- 切換從下一個停點起生效
- 回饋迴圈 3 輪仍未解決、角色卡住、需要只有你知道的資訊時，**任何模式都會停**

## 3.1 技術模組（前端／後端／AWS CDK）

PM 啟動時依專案內容自動偵測（monorepo 依子目錄），歡迎訊息會說明結果。

| 想做的事 | 對 PM 說 |
| --- | --- |
| 看偵測結果 | 「目前的模式和設定？」 |
| 修正偵測 | 「這個專案沒有前端」「啟用 CDK 模組」「這是 Vue 3 專案」 |
| 長期固定 | 在專案 `AGENTS.md` 寫「本專案：前端 Vue 2（`web/`）、後端 Fastify（`api/`）、CDK（`infra/`）」 |

## 3.2 規範與品質門檻（不經 PM 也能用）

規範是獨立的 Skill，平常直接用 Claude Code 開發時也會自動套用。

| 想做的事 | 對 Claude 說 |
| --- | --- |
| 查專案的技術組成 | 「偵測這個專案的技術模組」（腳本免確認執行的前提：該專案已接受過信任對話框） |
| 交付前自己檢查 | 「跑品質門檻」 |
| 依規範審查 | 「用 aws-cdk-standards 檢查這個 stack」「用 frontend-standards 審查這個元件」 |

## 4. 風險等級

| 想做的事 | 對 PM 說 |
| --- | --- |
| 覆寫 PM 的判定 | 「這次當成高風險」「這是低風險」 |
| 問判定理由 | 「為什麼判定為中風險？」 |

PM 會記錄原判定與覆寫原因。破壞性介面變更、有狀態資源、資源取代、IAM `*` 會被自動升級為高風險。

## 5. 回答問題（BA／設計師的問題檔）

| 想做的事 | 做法 |
| --- | --- |
| 自己作答 | 打開 PM 指定的問題檔，在每題 `[Answer]:` 後填選項字母，存檔後說「完成」 |
| 全部照建議 | 「全部採用建議」 |
| 大部分照建議 | 「採用建議，但 Q3 選 B」 |
| 選項都不合適 | 選最後一個「X) 其他」，在 `[Answer]:` 後寫說明 |

每題都附有「> 建議：…」，可以先看建議再決定。

## 6. 核准或要求修改

| 想做的事 | 對 PM 說 |
| --- | --- |
| 核准，進下一步 | 「繼續」或「核准」 |
| 要修改 | 直接說要改什麼，例如「錯誤訊息改成英文」「`01` 也要接受」 |
| 回饋迴圈超過 3 輪時決定 | 「先接受目前結果」「再給開發者一輪」「改需求：…」 |
| 範圍外的缺口 | 「另開一項工作」或「這次一起做」 |

## 7. 擴充規則

預設：**Security 啟用**；Resiliency、Property-Based Testing 停用；三者都不提問。

| 想做的事 | 對 PM 說 |
| --- | --- |
| 啟用 | 「啟用 Resiliency」「要做 PBT」 |
| 關閉 | 「關閉 Security」「這次不用 Resiliency」 |

Personal Team 規範（PTEAM-01～07）一律啟用，不能關閉。

## 10. 權限確認（不是對 PM 說，而是 Claude Code 跳出的視窗）

| 狀況 | 做法 |
| --- | --- |
| 寫高風險檔案（migration、`*.sql`、`infra/`、`cdk/`、`*-stack.ts`、`.github/workflows/`、`auth/`、`.env*`）跳出確認 | 看清楚內容後按「允許」。對話中的「核准」**不等於**寫檔權限 |
| 本機部署（`cdk deploy`、`sam deploy` 等）、`git push --force` 被拒絕 | 這是設計如此；部署請走 CI + OIDC |

## 11. 可以用的設定檔

| 設定 | 位置 |
| --- | --- |
| 權限關卡 | 專案的 `.claude/settings.json`（`ask`、`deny`）；migration 或 IaC 在其他路徑時自行補上 |
| 專案高風險路徑或模組 | 專案的 `AGENTS.md`，例如「`src/billing/` 屬高風險」，PM 會列入風險判定 |
| 專案的技術組成 | 專案的 `AGENTS.md`，例如「本專案：前端 Vue 3、後端 Fastify、CDK」，優先於自動偵測 |
| codebase-memory-mcp（選用） | 在 Claude Code 設定這個 MCP 後，設計師、開發者、審查者自動使用 |
